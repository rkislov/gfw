# Проверка управления сетью 10 ноября 2026 года

Версия 0.3.0-dev. Выполнены `go test -race ./...`, `go vet ./...`, проверка синтаксиса JavaScript и сборки статических Linux-бинарников для amd64 и arm64. Тесты покрывают модель зависимостей, опасные имена, циклы, пересечения подсетей, маршруты на портах, содержимое etcnet, резервирование файлов и режимов доступа, ETag/ревизии, права API и общий протокол сети/firewall.

Реальная сетевая проверка: изолированный контейнер ALT Linux p10 aarch64, etcnet 0.9.28-alt2, nftables 1.1.7, ядро Docker 7.0.14-linuxkit. Контейнер запускался с `--network none`, без опубликованных портов и с исходниками только для чтения. Внутри создавались отдельные LAN/WAN namespace, veth-порты и одноразовый журнал. Сеть компьютера разработчика не изменялась.

Успешно проверены:

- Создание bond active-backup из двух Ethernet/veth-портов, VLAN 100 поверх bond, bridge поверх VLAN.
- Статические IPv4/IPv6-адреса моста и маршруты обоих семейств.
- Генерация options/address/route/sysctl-файлов etcnet и protocol 186 у маршрутов GFW.
- Взаимное исключение применения сети и firewall, повтор ID без дублирования операции.
- Ручной откат с возвратом исходных IP, маршрутов, MAC и файлов физического порта; созданные виртуальные интерфейсы удаляются.
- SIGKILL и повторный запуск: неподтверждённое изменение откатывается в ядре и в файлах.
- Добавление вторичного IP LAN без потери доступа к прежнему и новому адресу; попытки выключить/удалить LAN или заменить все старые IP отклоняются.
- Настоящий 30-секундный тайм-аут сети: маршруты и файлы восстанавливаются без браузера и контроллера.
- Штатный `ifup br100` etcnet читает созданную конфигурацию и восстанавливает bond, VLAN, bridge, адреса и маршруты после удаления виртуальных устройств из ядра.
- Смена active-backup на 802.3ad отражается в ядре и BONDMODE=4. Удаление ещё используемого родителя VLAN отклоняется.
- Удаление управляемых виртуальных интерфейсов и последующий откат возвращают bridge/VLAN/bond и маршруты.
- Ранее реализованные проверки nftables, anti-lockout IPv4/IPv6, защиты чужих таблиц, подтверждения и восстановления также проходят.

В браузере на отдельной тестовой БД проверены вход, добавление VLAN и маршрута через формы, сохранение и сохранность после перезагрузки страницы. На macOS применение ожидаемо отключено.

Для проверки загрузки etcnet в контейнере использован лабораторный override MODPROBE=/bin/true в options.d: нужные типы интерфейсов уже созданы и проверены реальными операциями ядра Docker, а дерево модулей гостевой ОС в контейнере отсутствует. Поэтому проверен разбор и применение конфигурации штатными скриптами etcnet, но не загрузка модулей настоящего ядра ALT.

Полноценная перезагрузка ALT p10 с systemd и реальное согласование LACP с коммутатором остаются отдельными аппаратными/VM-проверками. Связность LACP не заявляется на основании создания интерфейса в namespace.

Повторение: `./scripts/test-network-alt-p10.sh`. Сценарий выполняет сначала регрессию firewall, затем сетевые испытания; включает два реальных 30-секундных ожидания тайм-аута.
