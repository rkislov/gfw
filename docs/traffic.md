# Журнал трафика

В разделе **Журнал трафика** администратор настраивает ClickHouse, видит состояние коллектора и ищет соединения и срабатывания правил. Компоненты GFW входят в один RPM. Сервер ClickHouse подключается отдельно.

## Подключение

1. В ClickHouse создайте базу и учётную запись GFW. Ей нужны `CREATE TABLE`, `INSERT` и `SELECT` в этой базе. GFW создаёт таблицу `gfw_traffic_v1` при первом подключении.
2. На ALT Linux p10 пакет устанавливает настройки загрузки модулей и включает учёт пакетов и байтов conntrack через sysctl. Для применения сразу после обновления без перезагрузки выполните `modprobe -a nf_conntrack nf_conntrack_netlink nfnetlink_log nft_log` и `sysctl -p /usr/lib/sysctl.d/55-gfw-traffic.conf`, затем запустите обновлённые службы. Для уже открытых соединений счётчики могут отсутствовать.
3. Если политика была применена до обновления, заново примените и подтвердите её в панели. С этого момента nftables отправляет срабатывания на NFLOG. Доступ к панели через LAN сохраняется системным правилом anti-lockout.
4. В разделе **Подключение к ClickHouse** укажите URL, базу и учётные данные. Для удалённого сервера используется HTTPS с проверкой сертификата, для локального также доступен `http://127.0.0.1:8123`. Пароль хранится в зашифрованном хранилище контроллера. Чтобы приостановить доставку, сохраните пустой адрес.

## Поиск и хранение

- События conntrack содержат прямые и обратные адреса и порты, признак NAT и накопительные счётчики ядра, когда они доступны. Для активных соединений агент делает ограниченный снимок при запуске, каждые пять минут и после потери сообщения netlink. Неполные снимки отмечаются в состоянии коллектора.
- NFLOG передаёт действие, ID правила, направление и ревизию. ID соединения позволяет открыть связанные события. Штатное ядро ALT p10 5.10.274-std-def передаёт NFLOG без метаданных conntrack. Для таких записей панель предлагает поиск соединений по адресу, порту, протоколу и устройству. Результаты этого поиска могут включать несколько соединений.
- Можно искать по IP или CIDR в обоих направлениях, порту, протоколу, действию, ID правила, ID соединения и устройству. Панель возвращает до 250 последних событий. Сроки TTL ClickHouse составляют 30 дней для соединений и 90 дней для срабатываний правил.
- Агент буферизует события в локальной SQLite-очереди до подтверждения записи ClickHouse. Повторная доставка сохраняет ID события, и поиск исключает дубли. При переполнении очереди в 50 000 записей старейшие вытесняются. Панель показывает размер очереди, возраст старейшей записи, вытеснения и потери коллектора.
- Срабатывания каждого правила ограничены 25 событиями в секунду с начальным пакетом до 50 событий. Панель показывает, сколько событий пропущено по лимиту с момента загрузки текущих правил. Фильтрация и anti-lockout продолжают работать при недоступности ClickHouse. Полезная нагрузка пакета в журнал не записывается.
