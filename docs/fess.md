# Публикации и WAF FESS

В разделе «Сайты и WAF» задайте адрес прослушивания, домен сайта, префикс пути и адрес HTTP(S) upstream. Для HTTPS выберите серверный сертификат домена из «Сертификаты и ACME». Маршруты одного домена используют один сертификат. Для запроса выбирается самый длинный подходящий префикс, который снимается перед передачей в upstream.

Сохраните черновик, проверьте конфигурацию, примените и подтвердите после проверки публикации. Таймер восстанавливает предыдущую конфигурацию. При перезапуске контроллер загружает последнюю подтверждённую ревизию. Модуль включается отдельно и поставляется в одном RPM. Панель и отдельный HTTP-01 listener резервируют свои TCP-порты. При проверке новой публикации FESS также пробует занять адрес прослушивания.

Локальные правила используют условия FESS. Пример для блокировки служебного файла:

```json
[
  {
    "id": "deny-env",
    "name": "Файл .env",
    "action": "block",
    "priority": 10,
    "condition": {"path_exact": "/.env"}
  }
]
```

В режиме журналирования совпадение записывается в журнал и запрос передаётся приложению. В режиме блокировки правило с действием `block` возвращает HTTP 403. Поддерживаются условия по методу, URI, пути, регулярному выражению пути, заголовкам, параметрам запроса и подстроке тела. Для правил, проверяющих тело, действует предел 1 МиБ и требуется исходное тело без Content-Encoding. Поддержка публикаций ограничена обычными HTTP-запросами без WebSocket.

Наборы Security Feed загружаются по сохранённой подписке. GFW сверяет SHA-256 с каталогом и сохраняет набор в черновике выбранного маршрута. После импорта набор включается отдельной галочкой. Журнал SQLite хранит до 2 000 последних совпадений с правилом и решением WAF.

GFW использует движок правил и сопоставление путей из FESS 2.2.5 через встроенный адаптер. Сетевой экран управляется Linux-агентом независимо. Доступ к опубликованным портам задаётся правилами firewall.
