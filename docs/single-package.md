# Единый пакет GFW для ALT Linux и Ubuntu

Результат сборки — **один пакет `gfw` для выбранной системы и архитектуры**. Для ALT Linux p10 и p11 выпускаются RPM aarch64 и x86_64. Для Ubuntu 26.04 LTS выпускаются DEB arm64 и amd64. Контроллер, агент, Go DNS, GoDHCP и FESS входят в состав пакета.

В пакете находятся `gfwd`, `gfw-agent` со встроенными DNS/DHCP и WireGuard, CA/ACME в контроллере и управление OpenVPN, IPsec и Suricata IDS/IPS через агент, встроенный Tailwind-интерфейс без CDN, две systemd-службы, команды `gfw-setup` и `gfw-sysctl`, документация и лицензии. Для ALT системные зависимости (`nftables`, `etcnet`, `iproute2`, `systemd`, `shadow-utils`, `openssl`, `openvpn >= 2.6`, `strongswan >= 5.9.13`, `suricata >= 8.0.4`, `tcpdump`) разрешаются пакетным менеджером. Для запуска GFW не требуются Go, Node.js или отдельный веб-сервер. Для долговременного журнала подключается отдельный экземпляр ClickHouse. [Журнал трафика](traffic.md). [Захват пакетов](capture.md). [Ранняя фильтрация XDP](xdp.md). [Ускорение транзита](flowtable.md).

## Сборка

Нужны Go 1.27+ и nfpm. Сборка не обращается к соседним репозиториям gdns/gdhcp: снимки исходников уже находятся в GFW.

```sh
make test check
GFW_PACKAGE_ARCH=amd64 make rpm
GFW_PACKAGE_ARCH=amd64 make rpm-alt-p11
GFW_PACKAGE_ARCH=amd64 make deb-ubuntu-26.04
# Для ARM64 задайте GFW_PACKAGE_ARCH=arm64.
```

Если nfpm отсутствует в PATH, передайте абсолютный путь через `GFW_NFPM`. Версия по умолчанию — 0.22.3; `GFW_PACKAGE_VERSION` позволяет задать следующую версию. Готовые файлы находятся в `dist/`. Сборки для разработки поставляются без подписи пакета.

## Установка

На выделенном шлюзе с уже настроенным статическим LAN выполните одну команду установки для вашей системы, затем запустите `gfw-setup`:

```sh
# ALT p10
apt-get install ./gfw-0.22.3-1.altp10.x86_64.rpm
# ALT p11
apt-get install ./gfw-0.22.3-1.altp11.x86_64.rpm
# Ubuntu 26.04
apt install --no-install-recommends ./gfw_0.22.3-1.ubuntu26.04_amd64.deb

# Первичная настройка на интерфейсе управления LAN
gfw-setup br-lan
```

При установке создаются системные пользователи `gfw`, `gfw-ids` и `gfw-capture` и закрытые каталоги. Первый запуск служб GFW выполняет команда `gfw-setup`. Первую политику firewall применяет администратор из панели. Команда `gfw-setup` проверяет существование указанного интерфейса и IPv4, создаёт первоначальный самоподписанный TLS-сертификат, фиксирует LAN и порт 8443, затем включает две службы. При существующем `agent.env` команда отказывается его перезаписывать: последующие изменения выполняются администратором с учётом журнала защиты LAN.

Откройте `https://<LAN-IP>:8443`. Первоначальный сертификат самоподписанный; установите доверенный сертификат для рабочего устройства. Ключ входа находится в `/var/lib/gfw/admin.token` и не выводится в журнал. DNS, DHCP, WireGuard и HTTP-01 listener при новой установке выключены. CA/ACME и управляемый TLS описаны в [инструкции сертификатов](certificates.md). Первый запуск не применяет автоматически базовую политику firewall: сохраните, проверьте и примените её в панели, затем включайте нужные сервисы.

На Ubuntu системные зависимости strongSwan и Suricata доступны из архива Ubuntu, включая компонент `universe`. GFW запускает собственные экземпляры управляемых VPN и IDS/IPS. Выделите для них необходимые порты и интерфейсы, если на машине уже работают самостоятельные экземпляры OpenVPN, strongSwan или Suricata.

На ALT GFW сохраняет сетевую конфигурацию через etcnet. На Ubuntu служба агента использует Netplan 1.2 и systemd-networkd. В панели доступны выделенные интерфейсы GFW, а исходный профиль LAN задаётся в Ubuntu. Правило LAN anti-lockout действует в обеих сборках. [Управление сетью](network-management.md).

При ручной установке: создайте `/etc/gfw/agent.env` по примеру, положите TLS-ключ/сертификат в `/etc/gfw/tls/`, дайте группе `gfw` чтение файлов (0640) и включите `gfw-agent.service` и `gfwd.service`. LAN и TCP-порт должны совпадать с фактическим доступом управления. Журнал агента защищает подтверждённую привязку LAN от произвольной замены.

Профиль маршрутизации поставляется как `/usr/share/gfw/gfw-routing.conf` и не включается автоматически. Для выделенного маршрутизатора его можно осознанно установить в `/etc/sysctl.d/`, как описано в инструкции firewall.

## Обновление и удаление

Перед обновлением остановите службы, сделайте согласованную резервную копию данных и установите новый `gfw` через пакетный менеджер. Затем запустите службы и проверьте состояние. Сам postinstall не перезапускает процессы.

Удаление пакета останавливает службы, но сохраняет `/etc/gfw`, `/var/lib/gfw` и `/var/lib/gfw-agent`, включая ключи, аренды и журнал восстановления. Правила/сеть не сбрасываются автоматически: их жизненный цикл требует отдельного решения администратора. Не удаляйте журнал восстановления при действующей таблице GFW.

Пакет проверяется установкой, запуском служб, применением политики и сохранением данных при повторной установке и удалении в изолированных стендах.
