# Захват пакетов

В панели **Захват пакетов** выберите интерфейс, направление и ограничения сессии. Добавьте фильтры по IPv4, IPv6, ARP, TCP, UDP, ICMP, ICMPv6, ESP, VLAN ID, IP или CIDR и портам источника и назначения. Порты можно перечислять через запятую и задавать диапазонами. В экспертном режиме доступно одно выражение libpcap, например `tcp and (dst port 443 or dst port 8443)`.

По умолчанию сохраняется полный пакет, видимый выбранной точке захвата. Чтобы записывать только начало пакета, укажите snaplen. PCAP содержит фактическую длину пакета и сохранённую длину. Открыть его можно в Wireshark или tcpdump.

## Выбор точки захвата

- **Автоматически** для входящих пакетов сначала пробует XDP в драйвере. При отказе использует AF_PACKET и показывает причину перехода в сессии. Для исходящего и двустороннего трафика используется AF_PACKET.
- **XDP в драйвере** и **XDP generic** выбираются явно. При отказе выбранного режима сессия не запускается. XDP работает на свободном Ethernet-интерфейсе с MTU до 3000. Программа захвата копирует подходящие входящие кадры и возвращает `XDP_PASS`. Если на интерфейсе уже подключена XDP-программа, её сохраняют и для захвата выбирают AF_PACKET.
- **AF_PACKET** использует tcpdump/libpcap с немедленной выдачей пакетов и буфером 16 МиБ. Входящие кадры, ранее отброшенные XDP, в этой точке недоступны. Для jumbo и логических интерфейсов используется AF_PACKET, если их поддерживает libpcap.

Фильтр применяется в ядре. Для XDP libpcap компилирует выражение в классический BPF, который GFW преобразует в eBPF. Кадры передаются через кольцевой буфер BPF без изменения системных настроек perf. Если выражение использует функции, которые не удаётся перенести, явно выбранный XDP возвращает ошибку. Фильтр по порту требует доступного транспортного заголовка. На внешнем интерфейсе VPN виден зашифрованный пакет. VLAN offload и агрегация пакетов могут менять представление кадров в точке захвата. GFW не меняет настройки offload.

## Сессии и хранение

Агент ведёт одну активную сессию на одном интерфейсе. По умолчанию сессия заканчивается по лимиту времени, размера файла или числа пакетов. При включённой ротации лимит размера закрывает текущий PCAP и открывает следующий, а длительность и число пакетов ограничивают всю сессию. Лимит отдельного файла — до 256 МиБ. В поле **Файлов в ротации** задайте от 2 до 256 файлов, включая записываемый. Когда лимит достигнут, самый старый файл сессии удаляется. Общий счётчик пакетов учитывает файлы, уже удалённые ротацией. В панели отдельно показаны удалённые файлы и потери источника захвата.

Каталог хранит до 32 сессий. Квота по умолчанию — 512 МиБ. При запуске резервируется место для всех файлов выбранной сессии, с дополнительным запасом свободного места на разделе в 128 МиБ. Для длинного захвата на выделенном томе задайте `GFW_CAPTURE_QUOTA_MIB` в `/etc/gfw/agent.env` и перезапустите агент. Завершённые сессии удаляются автоматически по истечении срока хранения от 1 часа до 7 суток.

Каталог SQLite и файлы PCAP лежат в `/var/lib/gfw-agent/captures`. Можно смонтировать отдельный том в этот каталог. Если задан другой путь через `-capture-dir`, разрешите его в настройке `ReadWritePaths` службы агента.

Агент синхронизирует закрываемый PCAP с диском в фоне, пока принимает пакеты в следующий файл. Закрытые файлы ротации можно скачивать во время захвата. У каждого PCAP есть номер и SHA-256. Сессия показывает число пакетов, потери и усечения. После аварийной остановки агент восстанавливает целые записи незавершённых файлов и помечает сессию как неполную. Старт, остановка, скачивание и удаление фиксируются в административном аудите. Полезная нагрузка остаётся в PCAP и может содержать чувствительные данные.

Агент, панель и модуль входят в один RPM GFW. Служба агента задаёт `LimitMEMLOCK=64M` для работы XDP на ядре p10. `tcpdump` устанавливается как зависимость из репозитория ALT.
