# Захват пакетов

В панели **Захват пакетов** выберите интерфейс, направление и ограничения сессии. Добавьте фильтры по IPv4, IPv6, ARP, TCP, UDP, ICMP, ICMPv6, ESP, VLAN ID, IP или CIDR и портам источника и назначения. Порты можно перечислять через запятую и задавать диапазонами. В экспертном режиме доступно одно выражение libpcap, например `tcp and (dst port 443 or dst port 8443)`.

По умолчанию сохраняется полный пакет, видимый выбранной точке захвата. Чтобы записывать только начало пакета, укажите snaplen. PCAP содержит фактическую длину пакета и сохранённую длину. Открыть его можно в Wireshark или tcpdump.

## Выбор точки захвата

- **Автоматически** для входящих пакетов сначала пробует XDP в драйвере. При отказе использует AF_PACKET и показывает причину перехода в сессии. Для исходящего и двустороннего трафика используется AF_PACKET.
- **XDP в драйвере** и **XDP generic** выбираются явно. При отказе выбранного режима сессия не запускается. XDP работает на свободном Ethernet-интерфейсе с MTU до 3000. Программа захвата копирует подходящие входящие кадры и возвращает `XDP_PASS`. Если на интерфейсе уже подключена XDP-программа, её сохраняют и для захвата выбирают AF_PACKET.
- **AF_PACKET** использует tcpdump/libpcap с немедленной выдачей пакетов и буфером захвата 16 МиБ. Это снижает риск пропуска последнего неполного блока при остановке захвата. Входящие кадры, ранее отброшенные XDP, в этой точке недоступны. Для jumbo и логических интерфейсов используется AF_PACKET, если их поддерживает libpcap.

Фильтр применяется в ядре. Для XDP libpcap компилирует выражение в классический BPF, который GFW преобразует в eBPF. Кадры передаются через кольцевой буфер BPF без изменения системных настроек perf. Если выражение использует функции, которые не удаётся перенести, явно выбранный XDP возвращает ошибку. Фильтр по порту требует доступного транспортного заголовка. На внешнем интерфейсе VPN виден зашифрованный пакет. VLAN offload и агрегация пакетов могут менять представление кадров в точке захвата. GFW не меняет настройки offload.

## Сессии и хранение

Агент ведёт одну активную сессию на одном интерфейсе. Она заканчивается по первому достигнутому ограничению, вручную или при остановке агента. Лимит файла — до 256 МиБ. Каталог хранит до 32 сессий и до 512 МиБ файлов. При запуске проверяется свободное место с резервом 128 МиБ. Завершённые файлы удаляются автоматически по истечении заданного срока от 1 часа до 7 суток.

Каталог SQLite и файлы PCAP лежат в `/var/lib/gfw-agent/captures`. Можно смонтировать отдельный том в этот каталог. Если задан другой путь через `-capture-dir`, разрешите его в настройке `ReadWritePaths` службы агента.

Скачивание доступно после закрытия файла. Сессия показывает SHA-256, число пакетов, потери и усечения. После аварийной остановки агент восстанавливает целые записи PCAP и помечает файл как неполный. Старт, остановка, скачивание и удаление фиксируются в административном аудите. Полезная нагрузка остаётся в PCAP и может содержать чувствительные данные.

Агент, панель и модуль входят в один RPM GFW. Служба агента задаёт `LimitMEMLOCK=64M` для работы XDP на ядре p10. `tcpdump` устанавливается как зависимость из репозитория ALT. В этой версии есть один PCAP на сессию. Многоинтерфейсный PCAPNG, кольцевая ротация и TC egress остаются в плане.
