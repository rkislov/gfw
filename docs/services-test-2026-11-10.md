# Проверка GFW 0.5 — 10 ноября 2026

## Реальные сервисы

Одноразовый привилегированный Docker-контейнер без внешней сети; userspace ALT Linux p10 aarch64, nftables 1.1.7, etcnet 0.9.28-alt2, ядро Docker 7.0.14-linuxkit. Все интерфейсы и namespace изолированы от хоста.

`make test-services-linux` завершился `ALL INTEGRATED SERVICES TESTS PASSED`. Проверены:

- Предыдущая базовая регрессия nftables: anti-lockout LAN по IPv4/IPv6 при запретах входа и выхода, блокировка WAN, владение таблицей, ручной откат, авария и восстановление, настоящий 30-секундный таймер, отказ позднего подтверждения.
- Встроенный DNS отвечает на реальные запросы по UDP и TCP из namespace LAN авторитетными записями локальной зоны.
- DHCP выполняет DISCOVER/OFFER/REQUEST/ACK на двух интерфейсах, включая управляемый VLAN; выдаёт резервации, правильный server identifier, DNS и срок аренды.
- Разрешение WAN UDP/67 в firewall не заставляет DHCP отвечать на WAN: сокет и обработчик ограничены выбранным интерфейсом.
- Изменение маршрута пересоздаёт управляемый VLAN. После изменения и после отката DHCP-сокет привязывается к новому интерфейсу и снова обслуживает клиента; аренда сохраняется.
- SIGKILL агента во время неподтверждённого изменения возвращает подтверждённые DNS/DHCP, DNS отвечает после рестарта, подтверждённые DHCP-аренды остаются в SQLite.
- Настоящий 30-секундный таймер сервисов возвращает DNS после временного отключения; позднее подтверждение отклоняется.
- Общие API наблюдения возвращают аренды и журнал DNS; параллельное применение firewall во время настройки сервисов запрещено.

Во время расширения теста исправлены интеграционные случаи VLAN: обработчик DHCP не должен повторно интерпретировать имя уже терминированного Linux VLAN как входящий trunk; после пересоздания интерфейса нужно перепривязать сокеты, включая путь отката.

## Единый RPM

Собраны альтернативные RPM `gfw` для aarch64 и x86_64. На ALT p10 aarch64 выполнены установка через rpm с проверкой зависимостей, проверка systemd unit-файлов через systemd-analyze, запуск **установленных** `/usr/sbin/gfwd` и `/usr/sbin/gfw-agent`, сохранение/проверка/применение/подтверждение DNS и DHCP через аутентифицированный API и проверка административного аудита. Затем выполнены повторная установка и удаление. БД, ключ входа, каталог аренд и журнал восстановления сохранены. Контрольные суммы установленных бинарников совпали со сборкой.

Команда воспроизведения: `GFW_NFPM=/path/to/nfpm make test-package-linux`. Стенд не запускает systemd как PID 1: проверена валидность unit-файлов, а службы запускаются непосредственно для проверки установленного кода.

## Контроллер, панель и тесты Go

Браузерный тест использовал отдельную временную БД: DNS-интерфейс/IP/ACL, локальная зона, DHCP-пул и MAC-резервация, включение модулей в черновике, сохранение, повторная загрузка и предпросмотр. На macOS применение отключено. Тестовые настройки не записывались в основную БД проекта.

`make test check`: Go race detector, vet, четыре JavaScript-модуля. Включённые тесты DNS/DHCP-ядер также проходят. Добавлены проверки валидации, конфликтов ревизий и независимого хранения, общего журнала и восстановления, запрета порта управления для DNS, зависимостей интерфейсов/IP, сохранения версии журнала при последующем применении firewall и отката сети при ошибке перепривязки сервисов.

## Границы

Пакет для x86_64 собран, но выполнение его кода в этом прогоне не проверялось. Штатное ядро ALT p10, загрузка узла с systemd как PID 1, SELinux-политика и физическое оборудование остаются отдельным этапом. Нагрузочные показатели не измерялись. В интеграции ещё нет DHCPv6, relay, DDNS, PXE, HA, DNS-фидов, DoH/DoT, долговременного журнала DNS, ClickHouse и захвата пакетов.
