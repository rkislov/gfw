# Проверка GFW 0.7 — 10 ноября 2026

## Среда

Go 1.27, macOS arm64 для контроллера и модульных проверок. Userspace ALT Linux p10 aarch64 в одноразовом Docker-контейнере `--privileged --network none`, ядро Docker 7.0.14-linuxkit с WireGuard. Интерфейсы/маршруты изменялись только в изолированных namespace контейнера.

## Пакетный стенд

`scripts/test-wireguard-alt-p10.sh` собирает Linux-агент, тестовый бинарник и образы ALT. Проверяются:

- Базовая регрессия nftables: владение таблицей, IPv4/IPv6 anti-lockout на LAN при запретах входа/выхода, блокировка WAN, первый откат, SIGKILL, восстановление после потери таблицы, настоящий 30-секундный таймер, позднее подтверждение и штатная остановка.
- Реальный WireGuard ядра с PSK, клиентский профиль из API, HTTP через зашифрованный туннель, маршруты и фактические handshake/RX/TX.
- Доступ к тестовому management listener на LAN сохранён; прямой входящий HTTP с WAN не разрешён.
- Адреса и маршруты, пересекающие LAN, чужой WG-интерфейс и удаление интерфейса подтверждённой VPN-зоны отклоняются.
- SIGKILL во время неподтверждённого изменения возвращает ключи, PSK, peers, адреса и маршруты подтверждённой конфигурации. После повторного handshake трафик проходит.
- Настоящий 30-секундный таймер WG возвращает прежний порт и трафик, позднее подтверждение запрещено.
- После удаления WG-интерфейса при остановленном агенте подтверждённый туннель восстанавливается. Чужой интерфейс и отдельная nft-таблица сохраняются.

Отдельный тест в изолированном ядре проверяет частично созданный интерфейс без alias: атомарная group-метка позволяет восстановление. Интерфейс без этой метки не принимается под управление. В найденной особенности netlink/kernel alias из запроса создания не сохранялся; теперь полный alias устанавливается отдельной операцией после атомарной group-метки.

В первой реализации интерфейс пересоздаётся при применении: удалённому клиенту иногда требуется новый handshake. Проверка HTTP после восстановления допускает время на этот обмен, а не подменяет его ручным пересозданием клиента.

## Go, API и пакет

`make test check` проходит с race detector, vet и проверкой шести JS-модулей. Добавлены проверки небезопасных AllowedIPs/endpoint/клиентского экспорта, шифрования/повреждения ключей и потери ключа устройства, независимых ревизий SQL, общей очереди, версии журнала, зависимостей, тайм-аута, частичной ошибки и повторного отката. Проверяется запрет экспорта ключа роли tunnel через поле клиентского ключа.

В едином RPM на ALT p10 aarch64 проверяются установка и зависимости, unit-файлы, сохранение/применение/подтверждение через установленный контроллер/агент, генерация защищённых WG-ключей и клиентский экспорт. Существующие сценарии DNS/DHCP, CA/PKI, реальные TLS-проверки и 30-секундный TLS-откат входят в пакетный тест. Повторная установка/удаление сохраняют данные и ключи.

В браузере проверены новая страница WireGuard, формы туннеля/peer и недоступность привилегированных операций без Linux-агента. Полный сценарий настройки и клиентский экспорт проверяются через реальный API на Linux; браузер на macOS не управлял сетью.

## Границы

Штатное ядро ALT p10, загрузка systemd как PID 1, физическое оборудование, публичный NAT и внешние VPN-клиенты в этом прогоне не проверены. Выполнение — aarch64; RPM x86_64 собирается отдельно. Нагрузочные показатели не измерялись. Default route на шлюзе, policy routing, DNS endpoint в рабочем peer, QR и импорт секретов не реализованы. Применение пересоздаёт туннели; сохранение handshake без паузы — последующая оптимизация.
