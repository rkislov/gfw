# Зоны, группы, stateful и NAT — GFW 0.4

В панели «Межсетевой экран» задаются зоны, группы адресов и сервисов, правила и NAT. Всё сначала сохраняется в общий черновик SQLite. Сохранение не меняет Linux-узел. Применение выполняет gfw-agent с проверкой nftables, подтверждением и автоматическим откатом; сеть и firewall используют одну очередь изменений.

## Последовательность настройки

1. Создайте нужные VLAN/bridge/bond в разделе сети, примените и подтвердите их.
2. Назначьте реальные интерфейсы зонам LAN, WAN, DMZ или VPN. Допустимы собственные зоны и несколько интерфейсов в зоне; один интерфейс принадлежит одной зоне. Защищённый LAN агента может входить только в LAN или зону управления. Пустая зона допустима до использования в активном правиле.
3. При необходимости создайте группы адресов и сервисов. Адресная группа содержит IPv4 **либо** IPv6; принимаются IP и корректные CIDR. Сервис содержит TCP, UDP либо оба протокола, порты и диапазоны, например `53, 8000-8100`. Вложенные группы, DNS-имена и динамические фиды пока не поддерживаются.
4. Добавьте правило: «Из зоны LAN», «В зону WAN», «Через устройство», нужные адреса/сервис и действие. Порядок правил имеет значение. Прямой адрес и группа на одной стороне взаимоисключающие; сервис заменяет ручной протокол и порт.
5. Для выхода с внутренними IPv4 добавьте NAT «Выход через адрес интерфейса» из LAN в WAN. Сам NAT не разрешает транзит: требуется правило LAN → WAN.
6. Сохраните, проверьте предпросмотр, примените и подтвердите доступ через LAN до окончания таймера.

Агент проверяет существование всех интерфейсов назначенных зон. Удалить управляемый интерфейс, который используется подтверждённой зоной, нельзя: сначала примените и подтвердите изменение зоны, затем меняйте сеть. Черновик зоны сам по себе не снимает зависимость.

## Stateful

Для новых баз stateful включён по умолчанию. При обновлении старой базы он остаётся выключенным: обновление не расширяет старую политику автоматически. Включение выполняется явно в панели.

Исходное направление проверяется по правилам на каждом пакете. Разрешённый пакет получает идентификатор текущей политики в младших 64 битах conntrack label; ответы проходят по этому идентификатору. После изменения политики прежний идентификатор перестаёт разрешать ответы. Если исходное направление по-прежнему разрешено, следующий его пакет обновит идентификатор. Отозванное разрешение не сохраняется за счёт общего правила established/related. При изменении политики возможна краткая задержка ответа до следующего исходящего пакета или повторной передачи TCP.

Старшие 64 бита labels сохраняются; conntrack mark не изменяется. Младшие 64 бита нельзя делить с другим управляющим ПО. При включённом IPS инспекция транзита предшествует разрешению stateful-ответов. Поддержка helpers/ALG ограничена.

Обязательные loopback, LAN anti-lockout и служебные правила IPv6 управления выполняются раньше пользовательских правил. Для IPv6 вне защищённого LAN требуется разрешить необходимый ICMPv6, включая обнаружение соседей; готовой политики WAN/IPv6/RA пока нет.

## NAT

Поддерживается IPv4:

- Masquerade: исходящий адрес выбирается выходным интерфейсом.
- SNAT: заданный фиксированный IPv4. Его наличие на интерфейсе/маршрутизацию обеспечивает администратор.
- Исключение из исходящего NAT: поместите выше общего masquerade/SNAT.
- DNAT: один входящий TCP/UDP-порт в один внутренний IPv4 и порт. Внешний адрес можно ограничить CIDR.
- Hairpin: внутренний клиент обращается к внутреннему серверу через внешний IPv4/32. Создаются ограниченные DNAT и masquerade для этого проброса; сервер видит адрес внутреннего интерфейса шлюза.

У DNAT есть явный флаг «Разрешить перенаправленный трафик». Он требует stateful и создаёт разрешение после пользовательских правил, ограниченное зонами, протоколом, исходным портом/адресом и внутренним адресом/портом. Пользовательский запрет раньше него имеет приоритет. Прямой доступ с WAN к внутреннему адресу не получает это разрешение. Если флаг выключен, разрешение нужно задать отдельным правилом. Фильтрующие правила видят адрес назначения **после** DNAT.

Hairpin требует включённого разрешения проброса, разных внешней и внутренней зон и фиксированного внешнего IPv4/32. Для hairpin исходящая трансляция формируется отдельно перед обычными исходящими NAT. NAT не может перехватить TCP-порт управления на защищённом LAN; агент также ставит исключение этого порта перед своими DNAT.

NAT применяется при создании соединения. Изменение или откат правил не удаляет глобально conntrack: существующее отображение адресов живёт до завершения/истечения записи. Новые фильтрующие правила и поколение stateful начинают действовать сразу, но это не равнозначно принудительному закрытию всех соединений. NAT66, диапазоны проброса портов, NAT из локального output и динамические внешние адреса hairpin пока не поддерживаются.

## Маршрутизация и установка

Агент не меняет глобальные sysctl при применении политики. На выделенном маршрутизаторе включите forwarding отдельно:

```sh
install -m 0644 deploy/gfw-routing.conf /etc/sysctl.d/90-gfw-routing.conf
sysctl -p /etc/sysctl.d/90-gfw-routing.conf
```

Профиль включает IPv4 и IPv6 forwarding. Это осознанная настройка роли устройства; IPv6 RA/SLAAC и прочие параметры сети нужно согласовать отдельно. Агент предупреждает при выключенном IPv4 forwarding. Проверьте маршруты, обратный путь и доступ через консоль перед вводом узла в эксплуатацию.

Нужны nftables с поддержкой inet NAT и conntrack labels в ядре. Проверено на userspace ALT p10 с nftables 1.1.7 в изолированном Linux-стенде; проверка штатного ядра ALT p10 и загрузки через systemd остаётся отдельным этапом.

В GFW 0.5 версия схемы SQLite — 3, журнала восстановления — до 4 после применения сервисов (не ниже 3 после применения firewall). Старый агент должен отказываться читать новый журнал. Перед обновлением остановите службы и сохраните БД с WAL/SHM и каталог восстановления согласованной резервной копией. Понижение версии без восстановления совместимой копии не поддерживается.

## Проверки

`make test check` — Go race, vet и синтаксис JavaScript. `make test-firewall-linux` — изолированный привилегированный Docker-стенд ALT p10 с реальными nftables и сетевыми namespace. Он не подключается к сети хоста. `make test-network-linux` проверяет etcnet и откат сети.
