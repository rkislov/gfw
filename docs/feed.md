# Подписка Security Feed

В разделе «Подписка Security Feed» сохраните API-ключ feed.kislovs.ru, нажмите «Проверить ключ» и «Загрузить данные». Интервал от 1 до 168 часов включает обновление по расписанию. Значение 0 оставляет ручной режим. Удаление ключа отключает расписание и сохраняет загруженный снимок.

GFW запрашивает защищённый каталог, IP/CIDR, домены и IOC по HTTPS и передаёт ключ в заголовке `X-Api-Key`. Для выбора каталога поставщика GFW указывает `User-Agent: GFW/1`, а встроенный GoDNS указывает `GDNS/1` при прямой загрузке с feed.kislovs.ru. Ключ хранится зашифрованным в каталоге `feed` внутри каталога данных контроллера. Для восстановления подписки включайте весь этот каталог в резервную копию вместе с `gfw.db`.

В панели доступны исходные файлы, нормализованные списки IP/CIDR и доменов, SHA-256, время последней успешной загрузки и ошибки. Нормализация удаляет дубликаты и приводит сети и домены к каноническому виду. В доменном списке допустимо до 5% некорректных записей. Они пропускаются при нормализации и сохраняются в исходном файле. Исходный IOC JSON сохраняет типы, значения, источники и дополнительные поля. Хэш относится к сохранённым исходным байтам. Устаревшим считается снимок старше 24 часов или двух интервалов обновления, если этот срок больше.

GFW публикует файлы в SQLite одной транзакцией после проверки. Ошибка TLS, HTTP, разбора или пустой набор оставляют последний корректный снимок. Резкое уменьшение числа записей требует ручного обновления с флажком «Принять сокращённый набор». После ошибки расписание повторяет попытку примерно через 15 минут. При отказе в авторизации проверьте ключ и состояние подписки у поставщика.

## Использование в правилах

В карточках «Межсетевой экран» и «DNS» укажите локальные исключения и нажмите «Добавить снимок в черновик». Для firewall допустимы IP/CIDR, для DNS — имена доменов. Нажмите «Перейти к применению», проверьте план, примените настройки и подтвердите их. Для DNS должен быть включён встроенный резолвер. Чтобы отключить фильтр, уберите его из черновика и примените настройки повторно.

- Firewall проверяет IPv4 и IPv6 у транзитных пакетов до правил разрешения и обработки ответного трафика. Он блокирует совпадения по источнику или назначению. Исключение действует только для адреса, с которым оно совпало. Для перенаправленного трафика проверяется адрес назначения после DNAT. Счётчики блокировок доступны у правил `gfw:feed:*` в таблице `inet gfw`. Правило доступа к панели через LAN действует независимо.
- DNS блокирует имена и их поддомены с ответом NXDOMAIN и записью `BLOCKED` в журнале запросов. Исключение также действует для поддоменов. Локальные авторитетные зоны сохраняют приоритет.
- Снимок закрепляется за черновиком по SHA-256. После очередной загрузки действующий фильтр остаётся на подтверждённом снимке. Можно закрепить свежий список вручную. При откате агент восстанавливает предыдущие правила и списки.
- На один фильтр действует лимит развёртывания 1 МиБ и до 256 исключений. При превышении черновик сохраняет прежнюю конфигурацию. Полный полученный файл по-прежнему доступен для скачивания.

Подключение наборов к FESS запланировано отдельно.

Файловые IOC доступны для ручной сверки загруженного файла и для алертов Suricata по полностью реконструированным HTTP-файлам. [Проверка файлов в панели](ids.md#файловые-ioc-из-security-feed).
