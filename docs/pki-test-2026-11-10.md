# Проверка GFW 0.6 — 10 ноября 2026

## Go и криптография

`make test check` проходит с race detector, vet и синтаксической проверкой пяти JS-модулей. Проверены:

- Выпуск CA и конечного сертификата, проверка цепочки через Go x509 и SAN.
- Несоответствие ключа, неверные SAN, срок за пределами CA и закрытый ключ внутри публичного PEM отклоняются.
- AES-GCM хранение закрытого ключа; неверный ключ устройства блокирует открытие хранилища; второй контроллер не может одновременно открыть тот же каталог.
- Отзыв локального сертификата, подпись и серийный номер в CRL, запрет использования отозванного сертификата.
- Тайм-аут TLS, откат при ошибке probe, восстановление подтверждённого назначения и отмена неподтверждённого после повторного открытия БД.
- Полный ACME HTTP-01 order через настоящий x/crypto/acme-клиент и локальный TLS ACME CA: аккаунт, order, authorization, challenge, CSR, finalize и сертификат, проверяемый тестовым CA.
- Повторный выпуск с тем же аккаунтом создаёт новую версию, сохраняет предыдущую и обновляет назначенный TLS. Недоступный CA сохраняет действующий сертификат и планирует повтор с задержкой.
- HTTP-01 ответ ограничен Host/токеном, посторонние пути и домены возвращают 404. Административные API требуют авторизации, метаданные/экспорт не раскрывают закрытые ключи, HTTP-режим не позволяет назначить сертификат HTTPS-панели.

Тестовый ACME CA заимствован из Go x/crypto v0.57.0 с лицензией BSD и адаптирован для TLS, корректных base64url-токенов и identifier. Он не входит в производственные бинарники. Внешние CA, включая Let's Encrypt staging/production, в этом прогоне не вызывались.

## Реальный процесс и ALT p10

`scripts/pki-lab.py` запускает настоящий `gfwd` на loopback с временными данными. Проверены новое TLS-соединение с новым fingerprint без перезапуска, подтверждение и рестарт, SIGKILL во время замены, возврат прежнего подтверждённого сертификата, настоящий 30-секундный таймер и отказ позднего подтверждения. Проверено отсутствие административного API на HTTP-01 listener и запрет отзыва активного сертификата. Итог: `ALL PANEL PKI/TLS TESTS PASSED`.

Тот же сценарий выполнен для **установленного** `/usr/sbin/gfwd` из единого RPM на userspace ALT p10 aarch64 в изолированном Docker-контейнере без внешней сети. Основной пакетный тест также проверил зависимости, установку, systemd-analyze verify, существующие DNS/DHCP и аудит, создание CA/сертификата установленным кодом, права 0600 для БД и ключа устройства, повторную установку и удаление с сохранением данных PKI. Итог: `ALL SINGLE PACKAGE TESTS PASSED`.

## Интерфейс

На временной БД в браузере проверены создание CA, серверный сертификат с DNS/IP SAN, отзыв, сохранение и повторная загрузка, сохранение ACME-профиля и блокировка сетевого выпуска при выключенном HTTP-01 listener. Тестовые сертификаты/профили не записывались в основную БД проекта.

## Ограничения

RPM x86_64 собран; выполнение проводилось на macOS arm64 и Linux aarch64. Штатное ядро ALT p10, systemd как PID 1, низкий TCP-порт с ambient capability в реальной системе, внешний DNS/NAT и публичная ACME-валидация требуют отдельной проверки. Staging/production требуют домена и явного согласия с условиями выбранного CA. DNS-01, wildcard, EAB, intermediate/offline CA, PKCS#12, private-key export, внешний CSR, OCSP и потребители кроме HTTPS-панели ещё не реализованы.
