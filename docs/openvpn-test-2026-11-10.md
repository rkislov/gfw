# Проверка GFW 0.8 — 10 ноября 2026

## Что реализовано

Подготовка клиентских профилей OpenVPN: формы в общей панели, сохранение в SQLite с ревизиями, проверка локальных сертификатов и явный аудируемый экспорт `.ovpn`. Управляемый сервер/клиент в Linux-агенте пока не реализован; в UI и API это явно обозначено. Не выполнялись изменения сети macOS или рабочего шлюза.

## Автоматические проверки

`make test check`: Go-тесты с race detector, vet и синтаксис всех JavaScript-файлов. Новые сценарии проверяют блокировку внедрения директив через поля, роли server/client, единый CA, сроки, отзыв обеих сторон, отсутствие ключей CA/сервера в экспорте, отказ при невозможности записать аудит, аутентификацию, CSRF, устаревшие ревизии, сохранение/удаление невалидных профилей, восстановление из SQLite и миграцию схемы 4 → 5 без изменения существующих модулей.

Фаззинг поля remote: около 746 тысяч входов за 6 секунд, ошибок не обнаружено.

## Настоящий OpenVPN на ALT p10

Userspace ALT Linux p10 aarch64, OpenVPN 2.6.19/OpenSSL 1.1.1w из репозитория ALT. Выполнение в одноразовом Docker-контейнере `--privileged --network none` на ядре Docker/LinuxKit; клиент помещён в отдельный network namespace, underlay — veth. CA и клиентский профиль формируются штатным кодом GFW. Серверные ключи тестовой стороны читает только код теста внутри пакета PKI.

Подтверждены:

- Экспортированный UDP-профиль устанавливает TLS 1.3/AES-GCM туннель и передаёт ICMP через TUN.
- Аналогичное подключение и передача пакетов через TCP.
- `route-nopull` отклоняет навязанные сервером подсеть и redirect-gateway; проверены реальные маршруты клиента.
- Другой действующий серверный сертификат того же CA отклоняется из-за несовпадения SHA256.
- Отозванный клиент не экспортируется повторно; после обновления CRL на тестовом сервере ранее выданный файл не проходит TLS-аутентификацию.

Команда воспроизведения: `make test-openvpn-linux`. Стенд не запускается обычным `go test`: требуется явный opt-in в изолированном контейнере.

## Пакет и браузер

RPM 0.8.0 собирается для aarch64 и x86_64. Установка и выполнение проверены на aarch64: оба бинарника из одного RPM, systemd unit verification, DNS/DHCP с подтверждением, WireGuard с экспортом, CA/ACME-хранилище, сохранение/проверка/экспорт OpenVPN и запрет экспорта после отзыва. Проверены реальный 30-секундный TLS-откат, восстановление после SIGKILL, повторная установка RPM и удаление с сохранением данных. Системные зависимости остаются зависимостями ALT; Go/Node/отдельный web server для установки не нужны.

В браузере на отдельном временном каталоге данных проверены вход, новый раздел, выбор сертификатов, проверка параметров, сохранение и сброс формы, запрет скачивания без отметки о секрете, скачивание `.ovpn` и повторная блокировка кнопки. Рабочие сертификаты и ключ входа для этих проверок не использовались.

## Границы

Штатное ядро ALT, загрузка systemd как PID 1, физическое оборудование, нагрузка, внешние Windows/macOS/мобильные VPN-клиенты и публичный NAT не проверялись. x86_64 — сборка RPM, без выполнения. Реального управления OpenVPN-процессами, автоматической доставки CRL, отключения сеансов, TAP, tls-crypt и full-tunnel профиля пока нет. Успешный стенд CRL не означает, что отзыв автоматически доставляется на внешний сервер.
